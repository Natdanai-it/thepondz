Computer Fundamentals

เข้าใจคอมพิวเตอร์ให้ลึกกว่าการใช้งานทั่วไป

WHY THIS MATTERS

ให้น้องมองคอมพิวเตอร์เป็นระบบที่รับข้อมูล ประมวลผล แสดงผล และจัดเก็บข้อมูล ไม่ใช่เพียงอุปกรณ์สำหรับเปิดเกมหรือโปรแกรม

เนื้อหาที่สอน

  • Computer คืออะไร และแตกต่างจากอุปกรณ์ดิจิทัลอื่นอย่างไร
  • แนวคิด Input → Process → Output → Storage
  • Hardware, Software และ Operating System ทำงานร่วมกันอย่างไร
  • ตัวอย่างการทำงานจริง เช่น กดแป้นพิมพ์ → ประมวลผล → แสดงผล → บันทึกไฟล์

ลงมือทำจริง

  • เปิดเครื่องจริงแล้วให้น้องชี้ว่าอะไรคือ Input / Output / Storage
  • เลือกกิจกรรมหนึ่ง เช่น พิมพ์ชื่อใน Word แล้วอธิบายว่าข้อมูลเดินทางอย่างไร
  • สร้างแผนภาพ IPO ของงานที่ตัวเองทำในคอมพิวเตอร์ 1 งาน

คำถามเพื่อฝึกคิด

  • ถ้าไม่มี Storage คอมพิวเตอร์ยังทำงานได้หรือไม่
  • Smartphone ถือเป็น Computer หรือไม่ เพราะอะไร
  • โปรแกรมกับไฟล์ต่างกันอย่างไร

Computer ไม่ได้มีแค่หน้าจอ

คอมพิวเตอร์คือระบบที่รับข้อมูล (Input) นำข้อมูลไปประมวลผล (Process) แสดงผล (Output) และเก็บข้อมูลไว้ใช้ภายหลัง (Storage) อุปกรณ์หนึ่งชิ้นอาจมีมากกว่าหนึ่งหน้าที่ เช่น Smartphone เป็นทั้ง Input, Process, Output และ Storage ในเครื่องเดียว.

Hardware / Software / Operating System

Hardware คือสิ่งที่จับต้องได้ เช่น CPU, RAM, Keyboard ส่วน Software คือชุดคำสั่งหรือโปรแกรม เช่น Word, Chrome และเกม ขณะที่ Operating System เช่น Windows เป็นตัวกลางที่ช่วยให้ผู้ใช้ โปรแกรม และ Hardware ทำงานร่วมกัน.

Data เดินทางอย่างไร

เมื่อพิมพ์คำว่า Hello บน Keyboard การกดปุ่มคือ Input ระบบและโปรแกรมนำข้อมูลไป Process ตัวอักษรปรากฏบนหน้าจอเป็น Output และเมื่อกด Save ข้อมูลถูกเขียนลง Storage.

บทพูด/ประโยคเปิดประเด็นของครู
  • วันนี้ครูไม่ได้จะสอนว่า Keyboard อยู่ตรงไหน แต่เราจะตามดูว่า “ข้อมูลเดินทางไปไหน” หลังจากเรากดปุ่มหนึ่งครั้ง
  • ลองคิดก่อนว่า ถ้าเครื่องมี CPU แต่ไม่มีหน้าจอ ยังถือว่าคอมพิวเตอร์ทำงานอยู่ไหม
  • ทุกครั้งที่น้องใช้คอม ให้ลองถาม 4 คำนี้: Input อะไร? Process อะไร? Output อะไร? เก็บไว้ที่ไหน?
คำถามเช็กความเข้าใจ
  • Smartphone ถือเป็น Computer หรือไม่ เพราะอะไร?
  • ถ้าไม่มี Storage เราดู YouTube ได้ไหม แล้วอะไรจะหายไป?
  • ไฟล์ PDF เป็น Hardware หรือ Software หรือ Data? เพราะอะไร?

Hardware & Computer Specifications

รู้จักสิ่งที่อยู่ภายในคอมพิวเตอร์และอ่านสเปกเป็น

WHY THIS MATTERS

เปลี่ยนจากการจำชื่อ CPU/RAM/GPU ไปสู่การเข้าใจว่าแต่ละส่วนมีหน้าที่อะไร และสเปกส่งผลต่อการใช้งานอย่างไร

เนื้อหาที่สอน

  • CPU, RAM, SSD/HDD, GPU, Mainboard และอุปกรณ์ต่อพ่วง
  • Capacity, Speed, Core, Memory, Storage และหน่วยที่ใช้บ่อย
  • RAM 8 GB กับ 16 GB ต่างกันอย่างไร
  • SSD 512 GB หมายถึงอะไร และเหตุใดความจุกับความเร็วจึงเป็นคนละเรื่อง
  • คอมพิวเตอร์สำหรับเรียน งานกราฟิก และเกมต้องการสเปกต่างกันอย่างไร

ลงมือทำจริง

  • เปิด Task Manager / System Information เพื่ออ่านสเปกเครื่องจริง
  • ทำ Spec Card ของเครื่องที่ใช้อยู่
  • เปรียบเทียบคอม 2–3 เครื่องแล้วเลือกให้เหมาะกับโจทย์ เช่น เรียนออนไลน์ ตัดต่อ หรือเล่นเกม

คำถามเพื่อฝึกคิด

  • เครื่องที่แพงกว่าจะดีกว่าทุกงานจริงหรือไม่
  • ถ้าเพิ่ม RAM แต่ CPU เดิม ผลจะเป็นอย่างไร
  • ถ้างบจำกัด ควรให้ความสำคัญกับส่วนใดก่อน

CPU = ผู้ประมวลผลหลัก

CPU ทำงานตามคำสั่งของโปรแกรม จำนวน Core/Thread และความเร็วมีผลต่อความสามารถ แต่ห้ามสรุปจากตัวเลขเดียว เพราะสถาปัตยกรรมและรุ่นมีผลด้วย.

RAM ≠ Storage

RAM เป็นพื้นที่ทำงานชั่วคราวสำหรับโปรแกรมที่กำลังเปิด ส่วน SSD/HDD เป็นพื้นที่เก็บไฟล์ระยะยาว RAM มากช่วยให้เปิดหลายงานได้ดีขึ้น แต่ไม่ได้แปลว่าเก็บรูปได้มากขึ้น.

GPU และ Workload

GPU เหมาะกับงานประมวลผลภาพ เกม 3D งานกราฟิก และงาน AI บางประเภท การเลือกคอมจึงต้องเริ่มจาก “จะเอาไปทำอะไร” ก่อนดูว่ารุ่นไหนแรงที่สุด.

Word & Document Creation

เปลี่ยนข้อมูลให้เป็นเอกสารที่อ่านง่ายและใช้งานต่อได้

WHY THIS MATTERS

Word เป็นเครื่องมือพื้นฐานสำหรับรายงาน คู่มือ ข้อเสนอ และงานที่ต้องการรายละเอียด จึงควรเรียนเกินระดับแค่พิมพ์ข้อความ

เนื้อหาที่สอน

  • Heading, Paragraph, Bullet, Numbering
  • Table, Picture, Crop, Caption, Hyperlink
  • Page Layout, Margin, Header/Footer
  • Styles และความสม่ำเสมอของเอกสาร
  • Export / Print to PDF

ลงมือทำจริง

  • สร้าง One-page Research Brief จากข้อมูลที่ค้นเอง
  • ทำคู่มือ How-to 1 เรื่องที่มีภาพประกอบและขั้นตอน
  • Export เป็น PDF และตรวจว่าหน้าตายังคงเหมือนต้นฉบับ

คำถามเพื่อฝึกคิด

  • ทำไม Heading ควรต่างจากการทำตัวอักษรใหญ่ด้วยมือ
  • เมื่อไรควรใช้ตารางแทน Bullet
  • เอกสารที่สวยแต่ค้นข้อมูลยากถือว่าดีหรือไม่

สร้างเอกสารที่มีโครงสร้าง ชัดเจน และพร้อมส่งให้ผู้อื่นอ่านได้

Structure ก่อน Decoration

เอกสารที่ดีเริ่มจาก Title, Heading, Paragraph, List, Table และลำดับข้อมูล ก่อนเลือกสีหรือฟอนต์.

Styles ทำให้เอกสารเป็นระบบ

การใช้ Heading Styles ทำให้รูปแบบสม่ำเสมอและช่วยสร้างสารบัญ/นำทางได้ ต่างจากการขยายฟอนต์ด้วยมือทุกหัวข้อ.

Editable vs Deliverable

DOCX เหมาะกับการแก้ไขต่อ ส่วน PDF เหมาะกับการส่งอ่าน/พิมพ์เพราะ Layout คงที่กว่า.

บทพูด/ประโยคเปิดประเด็นของครู
  • Word ไม่ใช่โปรแกรมพิมพ์ข้อความอย่างเดียว วันนี้เราจะทำ “เอกสารที่คนอื่นเปิดแล้วเข้าใจทันที”
  • ก่อนแต่งสี ให้เราจัดลำดับว่าคนอ่านควรเห็นอะไรเป็นอันดับหนึ่ง สอง และสาม
  • ตอนส่งงาน ถามเสมอว่าเขาต้องการ “แก้ไขต่อ” หรือ “อ่านอย่างเดียว”
คำถามเช็กความเข้าใจ
  • ทำไมใช้ Space หลายครั้งเพื่อจัดตำแหน่งจึงไม่ดี?
  • Heading ต่างจากข้อความ Bold อย่างไร?
  • เมื่อไรควรส่ง DOCX และเมื่อไรควรส่ง PDF?

Presentation Skills

เปลี่ยนข้อมูลให้กลายเป็นเรื่องที่คนอื่นเข้าใจได้เร็ว

WHY THIS MATTERS

การนำเสนอไม่ใช่การเอารายงานไปแปะลงสไลด์ แต่เป็นการเลือกสาระสำคัญและออกแบบการสื่อสาร

เนื้อหาที่สอน

  • Slide Structure และ Story Flow
  • Visual Hierarchy, Layout, Typography
  • Image, Icon, Chart และการลดข้อความ
  • ความแตกต่างระหว่าง Document กับ Presentation
  • การพูดประกอบสไลด์โดยไม่อ่านข้อความ

ลงมือทำจริง

  • เปลี่ยนรายงาน 1 หน้าให้เหลือ 3–5 Slides
  • ทำ Before/After เปรียบเทียบสไลด์ที่ข้อความแน่นกับสไลด์ที่สื่อสารดี
  • นำเสนอ 2 นาทีโดยจำกัดข้อความบนจอ

คำถามเพื่อฝึกคิด

  • ถ้าข้อมูลหายไปจากสไลด์มากเกินไปจะเกิดอะไร
  • คนดูควรเห็นอะไรเป็นอันดับแรก
  • Animation เพิ่มความเข้าใจหรือแค่เพิ่มความสวย
EXPECTED OUTCOME

ย่อสาระสำคัญและออกแบบสไลด์เพื่อการสื่อสารได้ ไม่ใช้สไลด์เป็นเอกสารอ่าน

One Slide = One Message

Visual Hierarchy

ขนาด ตำแหน่ง ช่องว่าง และ Contrast บอกคนดูว่าอะไรสำคัญก่อน ไม่ใช่ใช้สีเยอะ.

Slide สนับสนุนคนพูด

สไลด์ไม่ควรมี Paragraph ยาว เพราะคนดูจะอ่านแข่งกับผู้พูด ใช้ Keyword, Image, Chart และตัวเลขสำคัญแทน.

  • ก่อนใส่ Animation ให้ถามว่า Message ของ Slide นี้คืออะไร
  • วันนี้มีข้อห้าม: ห้ามอ่านข้อความจาก Slide ตรง ๆ

  • ทำไมภาพใหญ่ 1 ภาพอาจสื่อสารดีกว่าภาพเล็ก 8 ภาพ?
  • Animation ช่วย Message หรือแค่ทำให้เคลื่อนไหว?

Data Literacy

Excel & Data Thinking

ใช้คอมพิวเตอร์ช่วยจัดการและวิเคราะห์ข้อมูล

WHY THIS MATTERS

ฝึกให้น้องเห็นว่าคอมพิวเตอร์ไม่ได้มีไว้สร้างเอกสารอย่างเดียว แต่ช่วยคำนวณ มองหาแนวโน้ม และตัดสินใจจากข้อมูลได้

เนื้อหาที่สอน

  • Row, Column, Cell, Table
  • SUM, AVERAGE, MAX, MIN, COUNT
  • Sort, Filter และ Conditional Thinking เบื้องต้น
  • Chart และการเลือกกราฟให้เหมาะกับข้อมูล
  • Data → Question → Calculation → Insight

ลงมือทำจริง

  • ทำตารางเงินค่าขนม/คะแนน/เวลาอ่านหนังสือ 7–14 วัน
  • คำนวณรวม ค่าเฉลี่ย ค่าสูงสุด ค่าต่ำสุด
  • สร้างกราฟแล้วเขียน Insight 3 ข้อ
  • ปรับข้อมูลหนึ่งค่าแล้วดูว่าสูตรและกราฟเปลี่ยนอย่างไร

คำถามเพื่อฝึกคิด

  • ค่าเฉลี่ยบอกทุกอย่างหรือไม่
  • กราฟแบบไหนทำให้คนเข้าใจผิดได้
  • ถ้าเจอข้อมูลผิดหนึ่งแถว ผลสรุปจะเปลี่ยนไหม

ใช้ Spreadsheet เป็นเครื่องมือคิดและวิเคราะห์ ไม่ใช่เพียงตารางสำหรับพิมพ์ข้อมูล

Cell คือข้อมูลหนึ่งหน่วย

การจัดข้อมูลที่ดีมักใช้ 1 Row = 1 Record และ 1 Column = 1 Field ทำให้ Sort, Filter และ Formula ทำงานได้ง่าย.

Formula คือกติกาที่คำนวณซ้ำได้

SUM, AVERAGE, MIN, MAX, COUNT/COUNTIF และ IF ช่วยให้ไม่ต้องคำนวณด้วยมือเมื่อข้อมูลเปลี่ยน.

Chart ต้องตอบคำถาม

กราฟไม่ใช่ของตกแต่ง ต้องเลือกจากคำถาม เช่น เปรียบเทียบหมวดใช้ Column/Bar ดูแนวโน้มใช้ Line และดูสัดส่วนใช้ Pie เฉพาะกรณีที่เหมาะ.

บทพูด/ประโยคเปิดประเด็นของครู
  • Excel ไม่ได้มีไว้ทำตารางสวย ๆ มันมีไว้ตอบคำถามจากข้อมูล
  • ก่อนเขียนสูตร ให้ถามก่อนว่าเราต้องการรู้ “อะไร”
  • ถ้าเปลี่ยนข้อมูลหนึ่งค่า แล้วคำตอบทุกอย่างอัปเดตเอง นั่นคือพลังของ Spreadsheet

  • กราฟสวยแต่ตอบคำถามไม่ได้ ถือว่าดีไหม?
  • ค่าเฉลี่ยสูงแปลว่าทุกคนได้คะแนนสูงหรือไม่?

Claim, Evidence, Source

Claim คือสิ่งที่กล่าวอ้าง Evidence คือหลักฐาน และ Source คือที่มาของข้อมูล เราไม่ควรเชื่อ Claim เพียงเพราะเขียนมั่นใจ.

Authority / Date / Purpose / Evidence

ตรวจว่าใครเขียน เมื่อไร จุดประสงค์คืออะไร มีหลักฐานอะไร และแหล่งอื่นสอดคล้องหรือไม่ โดยเฉพาะหัวข้อที่เปลี่ยนตามเวลา.

Primary vs Secondary

แหล่งต้นทาง เช่น รายงานวิจัย/ประกาศหน่วยงาน/ข้อมูลผู้ผลิต มักช่วยยืนยันรายละเอียดได้ดีกว่าบทความที่เล่าต่อ แต่ต้องอ่านให้เข้าใจบริบท.

บทพูด/ประโยคเปิดประเด็นของครู
  • คำถามสำคัญไม่ใช่ “เว็บนี้สวยไหม” แต่คือ “ทำไมเราควรเชื่อข้อมูลนี้”
  • ถ้าเว็บสองเว็บพูดไม่ตรงกัน เราไม่ต้องรีบเลือกข้าง ให้หา Source ที่ใกล้ต้นทางขึ้น
  • Critical Thinking ไม่ใช่ไม่เชื่อทุกอย่าง แต่คือรู้ว่า “ต้องการหลักฐานแค่ไหนก่อนเชื่อ”
คำถามเช็กความเข้าใจ
  • เว็บไซต์ .org หรือ .edu ถูกเสมอหรือไม่?
  • บทความเก่า 10 ปีใช้ได้ไหม? ขึ้นอยู่กับอะไร?
  • ถ้าคนดังพูดเรื่องวิทยาศาสตร์ แต่ไม่มีหลักฐาน เราควรให้น้ำหนักอย่างไร?

Fake News & Online Content

ก่อนเชื่อ ก่อนแชร์ ต้องตรวจ

WHY THIS MATTERS

ฝึกใช้ Critical Thinking กับเนื้อหาที่เด็กเจอจริง เช่น ข่าวไวรัล รูปตัดต่อ Clickbait และบัญชีปลอม

เนื้อหาที่สอน

  • Clickbait และ Misleading Headline
  • Fake News, Edited Image, Fake Account
  • ข่าว vs ความคิดเห็น vs โฆษณา
  • หลัก Stop → Check → Compare → Decide
  • การตรวจ Context ของภาพหรือข้อความ

ลงมือทำจริง

  • เล่นเกม Spot the Fake จากตัวอย่างหลายระดับ
  • เปรียบเทียบ Headline กับเนื้อหาจริง
  • ตรวจภาพ/ข้อมูลด้วยการค้นหาต้นทาง
  • สร้าง Checklist ก่อน Share

คำถามเพื่อฝึกคิด

  • ข้อความที่คนแชร์เยอะเท่ากับจริงหรือไม่
  • ทำไมคนจึงแชร์สิ่งที่ยังไม่ตรวจ
  • การแชร์ข้อมูลผิดโดยไม่ตั้งใจมีผลอย่างไร

Emotion เป็นสัญญาณเตือน

เนื้อหาที่เร่งให้กลัว โกรธ ตื่นเต้น หรือแชร์ทันทีควรทำให้เราชะลอและตรวจเพิ่ม ไม่ใช่เพราะอารมณ์แปลว่าปลอม แต่เพราะมันทำให้เราตัดสินใจเร็ว.

ตรวจแบบหลายขั้น

STOP ก่อนแชร์ → CHECK ใครโพสต์/วันที่/URL → COMPARE กับแหล่งอื่น → DECIDE ว่าพอเชื่อหรือควรรอ.

บทพูด/ประโยคเปิดประเด็นของครู
  • ข่าวปลอมที่เก่งที่สุดมักไม่ดูปลอมชัด ๆ มันจะมีส่วนจริงปนอยู่
  • ถ้าโพสต์บอกว่า “แชร์ด่วนก่อนถูกลบ” นั่นคือสัญญาณให้เราช้าลง ไม่ใช่เร็วขึ้น
  • เราไม่จำเป็นต้องพิสูจน์ทุกอย่างเอง แค่รู้ว่าเมื่อไรควรหยุดและหาแหล่งเพิ่ม
คำถามเช็กความเข้าใจ
  • หัวข้อ Clickbait แปลว่าข่าวปลอมทุกครั้งไหม?
  • Screenshot เป็นหลักฐานเพียงพอหรือไม่?
  • ถ้ายังตรวจไม่ได้ เราควรทำอะไรแทนการรีบสรุป?

AI as a Tool

ใช้ AI ให้เก่งกว่าแค่ถามคำตอบ

WHY THIS MATTERS

น้องใช้ AI อยู่แล้ว จึงควรยกระดับจากการขอคำตอบเป็นการใช้ AI เป็นผู้ช่วยคิด สรุป เปรียบเทียบ และตรวจงาน โดยผู้เรียนยังเป็นคนตัดสินใจ

เนื้อหาที่สอน

  • AI ทำอะไรได้และทำอะไรไม่ได้
  • Prompt: Goal + Context + Constraints + Output
  • Ask → Check → Improve → Use
  • Hallucination และ Bias
  • ข้อมูลส่วนตัวที่ไม่ควรใส่ใน Prompt

ลงมือทำจริง

  • ถามคำถามเดียวกัน 3 Prompt แล้วเปรียบเทียบคุณภาพ
  • ให้ AI ช่วยร่าง แต่ต้องแก้ด้วยตัวเอง
  • เลือก Claim จากคำตอบ AI แล้วตรวจด้วย Source จริง
  • ทำ Prompt Version 1 → 2 → 3 พร้อมอธิบายว่าดีขึ้นอย่างไร

คำถามเพื่อฝึกคิด

  • AI รู้จริงหรือแค่สร้างคำตอบที่ดูน่าเชื่อ
  • เมื่อไรควร Search แทนถาม AI
  • ถ้า AI กับเว็บทางการตอบไม่ตรงกันควรทำอย่างไร
EXPECTED OUTCOME

ใช้ AI อย่างมีเป้าหมาย ตรวจสอบได้ และไม่ยกการตัดสินใจทั้งหมดให้ AI

Prompt คือการกำหนดงาน

Prompt ที่ดีบอก Context, Task, Constraints และ Output เช่น “อธิบายระบบสุริยะสำหรับเด็ก 10 ขวบในตาราง 5 แถว พร้อมคำถามท้ายบท” ชัดกว่าถามสั้น ๆ.

AI สร้างคำตอบ ไม่ได้รับประกันความจริง

AI อาจ Hallucinate ชื่อ แหล่งอ้างอิง ตัวเลข หรือรายละเอียด ผู้ใช้ต้องตรวจข้อมูลสำคัญจาก Source อื่น.

AI = Co-pilot

เหมาะกับ Brainstorm, Explain, Summarize, Compare, Draft, Generate Questions และ Feedback แต่ไม่ควรใช้แทนการคิด/ตัดสินใจทั้งหมด.

บทพูด/ประโยคเปิดประเด็นของครู
  • วันนี้เป้าหมายไม่ใช่ทำให้ AI ทำงานเก่งขึ้น แต่คือทำให้ “เรา” ใช้ AI เก่งขึ้น
  • ถ้า AI ตอบอย่างมั่นใจ นั่นยังไม่ใช่หลักฐาน
  • ทุกครั้งที่ใช้ AI ให้แบ่งว่า ส่วนไหน AI ช่วย และส่วนไหน Jayler ตรวจ/เลือกเอง
คำถามเช็กความเข้าใจ
  • AI อ้างเว็บไซต์หนึ่งเว็บ เราควรเชื่อ Link นั้นทันทีหรือไม่?
  • ถ้า AI ให้คำตอบสองครั้งไม่เหมือนกัน แปลว่าอะไร?
  • งานแบบไหนควรให้ AI ช่วยคิด แต่ไม่ควรให้ AI ตัดสินใจแทน?

Computational Thinking

WHY THIS MATTERS

ตอบโจทย์ผู้ปกครองโดยตรง: ฝึกคิดเป็นระบบก่อนเขียนโปรแกรม เพื่อให้น้องเห็นว่าแนวคิด Computing ใช้แก้ปัญหาในชีวิตจริงได้

เนื้อหาที่สอน

  • Decomposition — แยกปัญหาใหญ่
  • Pattern Recognition — มองหาสิ่งที่เกิดซ้ำ
  • Abstraction — เลือกเฉพาะข้อมูลสำคัญ
  • Algorithm — เรียงขั้นตอน
  • การทดสอบและปรับกระบวนการ

ลงมือทำจริง

  • แยก Project ใหญ่ เช่น จัดงานวันเกิด เป็นงานย่อย
  • หาสิ่งที่ซ้ำในกิจวัตรประจำวัน
  • ตัดข้อมูลที่ไม่สำคัญออกจากโจทย์หนึ่งข้อ
  • เขียน Flow ขั้นตอนของงานจริงก่อนใช้คอมพิวเตอร์

คำถามเพื่อฝึกคิด

  • ปัญหาใหญ่ควรเริ่มแก้จากส่วนไหน
  • ข้อมูลทุกอย่างจำเป็นต่อการตัดสินใจหรือไม่
  • ถ้า Algorithm ใช้งานได้แต่ช้ามาก ถือว่าดีหรือยัง

Logic & Algorithm

WHY THIS MATTERS

  • Loop / Repeat

  • เงื่อนไขสองข้อชนกันจะเกิดอะไร

Condition

Loop

Variable

  • Condition คือจุดที่ Algorithm “เลือกทาง”
  • Loop คือคำตอบเมื่อเราพบ Pattern ของงานที่ต้องทำซ้ำ

  • เปลี่ยน Requirement แล้วแก้ Code ให้รองรับ

  • ถ้า AI เขียน Code ให้แต่เราอธิบายไม่ได้ ถือว่าทำได้จริงหรือยัง

WHY THIS MATTERS

เนื้อหาที่สอน

  • Password / Passphrase
  • 2FA
  • Phishing, Scam, Fake Website
  • Malware และการ Download อย่างปลอดภัย
  • Privacy และ Personal Information

ลงมือทำจริง

  • วิเคราะห์ตัวอย่างข้อความหลอกหลายรูปแบบ
  • ทำ Password Strength Challenge โดยไม่ใช้รหัสจริง
  • ตรวจ URL จำลองก่อนกด
  • สร้าง Incident Plan: ถ้าบัญชีถูกยึดต้องทำอะไรตามลำดับ

คำถามเพื่อฝึกคิด

  • ทำไม Password เดียวทุกบัญชีจึงเสี่ยง
  • OTP ควรบอกคนอื่นหรือไม่
  • ข้อความจากคนรู้จักเชื่อได้ทันทีหรือไม่ถ้าบัญชีเขาถูกแฮ็ก

  • ถ้ามีคนรู้ Password ของเรา 2FA คือประตูชั้นที่สอง
  • ข้อเสนอที่เร่งให้ทำทันทีคือจังหวะที่เราควรช้าที่สุด

Problem Before Product

อย่าเริ่มจาก “อยากทำเว็บ” ให้เริ่มจาก “มีปัญหาอะไร/ผู้ใช้ต้องการอะไร” แล้วค่อยเลือกว่าผลลัพธ์ควรเป็นเว็บ แบบฟอร์ม Dashboard หรือสื่อ.

MVP & Iteration

สร้างเวอร์ชันที่แก้ปัญหาหลักได้ก่อน ทดสอบกับคนจริง รับ Feedback แล้วปรับแทนการทำให้ใหญ่ตั้งแต่ครั้งแรก.

Ownership

ผู้เรียนต้องอธิบายเหตุผลของการเลือกข้อมูล เครื่องมือ และการตัดสินใจได้ แม้ใช้ AI หรือ Template ช่วย.

บทพูด/ประโยคเปิดประเด็นของครู
  • คาบนี้ครูจะตอบคำถาม “ทำยังไง” ให้น้อยลง แต่จะถามกลับว่า “น้องคิดว่ามีทางเลือกอะไรบ้าง”
  • ผลงานที่ดีไม่ใช่ชิ้นที่มี Feature เยอะที่สุด แต่คือชิ้นที่แก้โจทย์ชัดและอธิบายได้
  • ถ้าน้องติด ให้แยกปัญหาเป็นส่วนเล็กก่อน ไม่ต้องรีบเปลี่ยนเครื่องมือ
คำถามเช็กความเข้าใจ
  • เรารู้ได้อย่างไรว่าปัญหานี้มีจริง?
  • Feature ไหนจำเป็นต่อ MVP และ Feature ไหนทำทีหลังได้?
  • ถ้าคนใช้ไม่เข้าใจผลงาน เราควรโทษผู้ใช้หรือปรับงาน?
  • ส่วนไหน AI ช่วย และส่วนไหนผู้เรียนเป็นคนตัดสินใจ?
