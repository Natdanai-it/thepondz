WEB SYSTEMS9 นาที

เว็บ Static หรือ Backend เลือกแบบไหนดี

เปรียบเทียบเว็บ HTML บน GitHub Pages กับระบบที่มีฐานข้อมูล Login API และสิทธิ์ผู้ใช้ พร้อมข้อจำกัดด้านความปลอดภัย

ขอบเขตและข้อควรระวัง

รหัสผ่านที่เขียนไว้ใน JavaScript หรือซ่อนด้วย CSS ไม่ใช่ระบบ Login ที่ปลอดภัย ผู้เข้าชมดาวน์โหลด Source และตรวจค่าได้

สรุปก่อนเริ่ม

เว็บ Static เหมาะกับ Portfolio, Landing Page, เอกสาร และบทความ ส่วนงานที่มีบัญชีผู้ใช้ ข้อมูลเปลี่ยนแปลง หรือสิทธิ์รายคนมักต้องมี Backend

1. เว็บ Static ทำอะไรได้ดี

โหลดเร็ว ต้นทุนต่ำ Deploy ง่าย และพื้นผิวโจมตีน้อย เหมาะกับข้อมูลสาธารณะ สามารถใช้ JavaScript เพิ่ม Search, Filter และ Interactive UI ได้โดยไม่ต้องมี Server

2. เมื่อไรต้องมี Backend

เมื่อมี Login, Database, Upload, Payment, Email automation, Audit log, การอนุมัติ หรือข้อมูลเฉพาะผู้ใช้ Backend จะตรวจสิทธิ์และเก็บ Secret ฝั่ง Server แทนการส่งทุกอย่างไป Browser

3. ข้อจำกัดของ Client-side Password

การเข้ารหัสไฟล์ก่อนเผยแพร่ช่วยไม่ให้เห็นเนื้อหาโดยตรงและเหมาะกับการแชร์กลุ่มเล็ก แต่ยังไม่มีบัญชีรายคน การหมดอายุ การเพิกถอนสิทธิ์ หรือ Log หากรหัสกลุ่มหลุดต้องเปลี่ยนและเข้ารหัสใหม่

4. วิธีเลือกโดยไม่ทำระบบเกินจำเป็น

เริ่มจากข้อมูลเป็น Public หรือ Private ใครต้องแก้ข้อมูล ต้องมีสิทธิ์กี่ระดับ และต้องเก็บประวัติหรือไม่ หากเป็นหน้าแนะนำบริการใช้ Static หากเป็น Portal ลูกค้าให้เลือก Backend/Auth ที่รองรับสิทธิ์จริง

คำถามที่พบบ่อย

GitHub Pages ทำระบบ Login ที่ปลอดภัยได้ไหม?

GitHub Pages เป็น Static hosting จึงไม่ควรฝัง Secret หรือรหัสผ่านตรงใน JavaScript ระบบบัญชีผู้ใช้จริงต้องพึ่ง Auth และ Backend

ไฟล์เข้ารหัสด้วยรหัสกลุ่มปลอดภัยแค่ไหน?

เหมาะกับกลุ่มเล็กและลดการเปิดอ่านตรง ๆ แต่ไม่มีการเพิกถอนรายคน วันหมดอายุ หรือ Audit log หากรหัสหลุดต้องเปลี่ยนชุดข้อมูล
