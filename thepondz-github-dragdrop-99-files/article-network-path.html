0x80070035 และ Network Path ควรไล่ตรวจอะไรบ้าง?

ตรวจปัญหา Network Path และ File Sharing บน Windows จาก IP, Gateway, DNS, Firewall ไปจนถึง Permission อย่างเป็นลำดับ

เผยแพร่ 1 ก.ย. 2569·ปรับปรุง 2 ก.ย. 2569
ขอบเขตและข้อควรระวัง

เหมาะกับ Windows ในบ้านหรือสำนักงานทั่วไป หากเป็นระบบองค์กรหรือ Domain ควรแจ้งผู้ดูแลก่อนเปลี่ยน Policy และไม่ควรปิด Firewall ทั้งระบบเพื่อทดลอง

สรุปก่อนเริ่ม

แยกก่อนว่าเครือข่ายเสียหรือเฉพาะ Shared Folder เสีย การทดสอบด้วย IP และชื่อเครื่องจะช่วยชี้ว่าควรตรวจ Connectivity, Name Resolution หรือ Permission ต่อ

1. แยก Network ออกจาก File Share

ลองเปิดเว็บไซต์และ Ping Default Gateway หากอินเทอร์เน็ตกับ Gateway ใช้ได้ แต่เปิด Shared Folder ไม่ได้ ปัญหามักอยู่ที่ชื่อเครื่อง เส้นทาง Share, Firewall, Service หรือ Permission มากกว่าเครือข่ายทั้งหมด

2. ทดสอบด้วย IP และชื่อเครื่อง

  1. ใช้ ipconfig ดู IPv4 และ Default Gateway
  2. ลอง ping IP-ปลายทาง
  3. เปิด \\IP-ปลายทาง\ชื่อแชร์
  4. เปรียบเทียบกับ \\ชื่อเครื่อง\ชื่อแชร์

หากเปิดด้วย IP ได้แต่ชื่อเครื่องไม่ได้ ให้ตรวจ DNS, NetBIOS หรือ Name Resolution ก่อนแก้ Permission

3. ตรวจการแชร์และสิทธิ์

  • Network Profile ควรเป็น Private เฉพาะเครือข่ายที่เชื่อถือได้
  • เปิด Network Discovery และ File and Printer Sharing
  • ตรวจทั้ง Share Permission และ NTFS Permission
  • ตรวจบัญชีผู้ใช้และ Credential ที่เครื่องปลายทางยอมรับ

4. สิ่งที่ไม่ควรทำทันที

อย่าเปิด SMB1, ปิด Firewall หรือให้ Everyone Full Control โดยไม่ทราบสาเหตุ เพราะเพิ่มความเสี่ยงและทำให้หาต้นเหตุจริงยากขึ้น ควรเปลี่ยนทีละค่าและทดสอบซ้ำทุกครั้ง

คำสั่งที่ใช้ตรวจ

ipconfig
ping 192.168.1.1
\\ชื่อเครื่อง\ชื่อแชร์
