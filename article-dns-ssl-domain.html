WEB SYSTEMS9 นาที

Domain, DNS และ SSL/TLS ทำงานร่วมกันอย่างไร

เข้าใจ A, CNAME, MX, TXT, Certificate และลำดับตรวจเมื่อเว็บเข้าไม่ได้หรือ HTTPS เตือน

เผยแพร่ 1 ก.ย. 2569·ปรับปรุง 2 ก.ย. 2569
ขอบเขตและข้อควรระวัง

การแก้ DNS อาจกระทบทั้งเว็บและอีเมล ควรสำรองค่าเดิมและตรวจ Record ทุกชนิดก่อนเปลี่ยน Nameserver หรือ Zone

สรุปก่อนเริ่ม

Domain คือชื่อที่ผู้ใช้จำ DNS บอกว่าชื่อนั้นต้องไปที่ใด ส่วน SSL/TLS ยืนยันตัวตนเว็บไซต์และเข้ารหัสการรับส่งข้อมูล

1. DNS Record ที่พบบ่อย

  • A/AAAA: ชี้ชื่อไป IPv4/IPv6
  • CNAME: ชี้ชื่อหนึ่งไปอีกชื่อ
  • MX: ระบุระบบรับอีเมล
  • TXT: ใช้ยืนยันบริการและนโยบาย SPF/DKIM/DMARC

2. SSL/TLS Certificate ทำอะไร

Certificate ผูกชื่อ Domain กับกุญแจสาธารณะ Browser ตรวจผู้ออกใบรับรอง ชื่อโดเมน วันหมดอายุ และ Certificate chain หากชื่อไม่ตรงหรือหมดอายุจะขึ้นคำเตือน แม้ DNS ยังชี้ถึง Server ได้

3. ลำดับตรวจเมื่อเว็บเข้าไม่ได้

  1. ตรวจ Domain หมดอายุหรือไม่
  2. ตรวจ Nameserver และ DNS Record
  3. ตรวจว่า IP/ปลายทางตอบสนอง
  4. ตรวจ Hosting และ Virtual Host
  5. ตรวจ Certificate และ Redirect HTTP→HTTPS

4. เปลี่ยนค่าอย่างปลอดภัย

ลด TTL ล่วงหน้าหากมีแผนย้ายระบบ บันทึก Zone เดิม ตรวจทั้ง Root domain และ www ทดสอบจากหลาย DNS resolver และอย่าลบ MX/TXT ของอีเมลโดยไม่จำเป็น
