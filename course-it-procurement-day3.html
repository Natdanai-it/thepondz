MODULE 01 · TOPIC 001–019

Procurement Process, Requirement & Sources of Truth

19 หัวข้อ
001

ภาพรวมกระบวนการจัดซื้อ IT

กระบวนการจัดซื้อสินค้า IT ไม่ควรเริ่มจากการหาราคาถูกที่สุด

ลำดับที่เหมาะสมคือ

Requirement ↓ Understand ↓ Verify Specification ↓ Search Product ↓ Compare ↓ Check Compatibility ↓ Check Lifecycle ↓ Commercial Comparison ↓ IT Approval ↓ Purchase

002

Requirement คืออะไร

Requirement คือเงื่อนไขหรือความต้องการที่สินค้า/บริการต้องมี

ตัวอย่าง

Business Notebook RAM ≥ 16GB SSD ≥ 512GB NVMe Windows 11 Pro Warranty ≥ 3 Years

ไม่ได้หมายความว่า

ต้องซื้อ Notebook รุ่นหนึ่งรุ่นเดียวเท่านั้น

หาก IT อนุญาตให้เสนอ Equivalent Product

สามารถหารุ่นอื่นที่ตรงเงื่อนไขได้

003

Requirement กับ Model ต่างกันอย่างไร

Model-based Requirement

ระบุรุ่นชัดเจน

ตัวอย่าง

Lenovo ThinkPad รุ่น XXX

Specification-based Requirement

ระบุคุณสมบัติ

ตัวอย่าง

Business Notebook RAM 16GB SSD 512GB Windows 11 Pro

Brand-specific Requirement

ระบุ Brand

Dell เท่านั้น

Brand-neutral Requirement

ไม่กำหนดยี่ห้อ

หรือเทียบเท่า

004

คำว่า “หรือเทียบเท่า” หมายถึงอะไร

คำว่า

Equivalent

ไม่ได้หมายความว่า

ราคาใกล้กัน

หรือ

หน้าตาเหมือนกัน

แต่หมายถึงสินค้าที่มีคุณสมบัติสำคัญตรงหรือสูงกว่า Requirement และสามารถใช้งานแทนได้ตามวัตถุประสงค์

005

ก่อนหาของทดแทน ต้องเข้าใจของเดิมก่อน

สมมติฝ่าย IT ขอ

Switch Model A

แต่ Vendor แจ้งว่า

Discontinued

สิ่งแรกที่ควรทำไม่ใช่ Search

“Switch รุ่นใกล้เคียง”

แต่ต้องหา Specification ของ Model A ก่อน

เช่น

  • Port
  • Speed
  • PoE
  • PoE Budget
  • Uplink
  • VLAN
  • Management
  • Warranty
006

ทำไมต้องหาสเปคของรุ่นเดิมก่อน

ถ้าไม่รู้ว่าของเดิมมีอะไร

จะไม่สามารถพิสูจน์ได้ว่า

รุ่นใหม่แทนได้หรือไม่

ตัวอย่าง

Model A

24-Port PoE+ PoE Budget 370W

Model B

24-Port PoE+ PoE Budget 195W

ถ้าดูเพียง

24-Port PoE+

อาจคิดว่าเหมือนกัน

แต่จริง ๆ ต่างกันมาก

007

Sources of Truth

ข้อมูลสินค้า IT ควรยืนยันจากแหล่งที่น่าเชื่อถือ

ลำดับที่ควรใช้

1. Manufacturer Website

เว็บไซต์ผู้ผลิต

2. Official Datasheet

เอกสารสเปคทางการ

3. Product Guide / QuickSpecs

เอกสารรายละเอียดผลิตภัณฑ์

4. Compatibility Matrix

ตารางรองรับอุปกรณ์หรือ Software

5. Lifecycle Document

ข้อมูล EOL / EOS / Replacement

6. Authorized Distributor / Vendor

ใช้ประกอบเรื่องราคาและ Availability

008

Datasheet คืออะไร

Datasheet คือเอกสารจากผู้ผลิตที่ระบุรายละเอียดสินค้า

มักมีข้อมูล เช่น

  • Model
  • Specification
  • Performance
  • Interface
  • Capacity
  • Environment
  • Warranty
  • Feature

ควรใช้ Datasheet เป็นหลักในการ Verify

011

Part Number / SKU สำคัญมาก

สินค้า Series เดียวกันสามารถมีหลาย Configuration

ตัวอย่าง

Notebook Model ABC

SKU 001

Core Ultra 5 RAM 16GB SSD 512GB Windows Home

SKU 002

Core Ultra 7 RAM 32GB SSD 1TB Windows Pro

ดังนั้น

Model ABC

012

Manufacturer Configurable Product

Server และ Enterprise Hardware บางประเภทไม่ได้มี Spec ตายตัว

ตัวอย่าง Server รุ่นเดียวกันอาจเลือกได้

  • CPU 1 หรือ 2 ตัว
  • RAM 32GB ถึง 2TB
  • Disk หลายประเภท
  • RAID Controller
  • Network Card
  • PSU
  • Warranty

จึงต้องตรวจ

Configuration / BOM / Part Number

013

BOM คืออะไร

BOM ย่อมาจาก

Bill of Materials

เป็นรายการส่วนประกอบที่อยู่ในสินค้าหรือ Solution

ตัวอย่าง Server BOM

  • Server Chassis
  • CPU × 2
  • RAM × 8
  • SSD × 4
  • RAID Controller
  • Network Adapter
  • PSU × 2
  • Warranty
014

Vendor 2 รายอาจเสนอ

แต่ราคาไม่เท่ากัน

อาจเพราะ Configuration ต่างกัน

RAM 128GB

Vendor B

RAM 256GB

หรือ

Vendor A

Single PSU

Vendor B

Dual PSU

ดังนั้นต้องเทียบ BOM ไม่ใช่แค่ชื่อ Server

015

วิธีแยก Requirement

ควรแบ่ง Requirement เป็น 3 ระดับ

Must Have

ขาดไม่ได้

Should Have

ควรมี

Optional

มีก็ดี แต่ไม่ใช่เงื่อนไขหลัก

016

Must Have คืออะไร

Requirement ที่สินค้าไม่สามารถขาดได้

ตัวอย่าง Notebook

  • Windows 11 Pro
  • RAM ≥ 16GB
  • SSD ≥ 512GB NVMe
  • LAN Port
  • Warranty ≥ 3 Years

ถ้าขาดข้อใดข้อหนึ่ง

อาจไม่สามารถใช้งานตาม Requirement

017

Should Have

คุณสมบัติที่ต้องการ แต่สามารถให้ IT พิจารณาผ่อนปรนได้

เช่น

  • น้ำหนักไม่เกิน 1.5kg
  • Wi-Fi 6E
  • Keyboard Backlight
  • USB-C Charging

ถ้ารุ่นที่หาได้ไม่มี

อาจเสนอ Alternative

018

Optional

Feature ที่ไม่ใช่สาระสำคัญ

เช่น

  • สี
  • Fingerprint
  • Webcam Resolution ที่สูงขึ้น
  • Touchscreen

ขึ้นอยู่กับ Use Case

019

อาจแบ่งเป็น

MODULE 02 · TOPIC 020–033

Performance Comparison — CPU, GPU, RAM, Storage & Interface

14 หัวข้อ
020

Performance Requirement กับ Model Requirement

บางครั้ง IT ระบุ

Intel Core i7

เพราะต้องการ Performance ระดับหนึ่ง

หากรุ่นเดิมไม่มี

อาจเสนอ

Core Ultra 5 รุ่นใหม่

ที่ Performance เท่ากันหรือสูงกว่า

แต่ต้องมีหลักฐานรองรับ

021

Benchmark คืออะไร

Benchmark คือการทดสอบ Performance ของ Hardware ด้วยวิธีมาตรฐาน

ใช้เปรียบเทียบ

  • CPU
  • GPU
  • Storage
022

Benchmark ไม่ใช่ Requirement ทั้งหมด

CPU B ได้คะแนน Benchmark สูงกว่า CPU A

ไม่ได้หมายความว่า Notebook B ใช้แทนได้ทันที

เพราะยังต้องดู

  • RAM
  • Storage
  • Port
  • OS
  • Warranty
  • Compatibility

Benchmark เป็นเพียงหนึ่งปัจจัย

023

วิธีเทียบ CPU

ตรวจ

  1. Model เต็ม
  2. Generation
  3. Core / Thread
  4. Clock
  5. Architecture
  6. Power Class
  7. Benchmark
  8. Use Case
024

ตัวอย่าง CPU Comparison

MODULE 03 · TOPIC 034–045

Compatibility, EOL / EOS & Replacement Search

12 หัวข้อ
034

Compatibility คืออะไร

Compatibility คือความสามารถของสินค้าใหม่ในการทำงานร่วมกับระบบเดิม

ต้องตรวจ

Hardware Compatibility

ใช้ร่วมกันทางกายภาพได้หรือไม่

Software Compatibility

Software รองรับหรือไม่

Version Compatibility

Firmware / OS Version รองรับหรือไม่

Vendor Compatibility

ผู้ผลิตรับรองหรือไม่

035

ตัวอย่าง Hardware Compatibility

Server รองรับ

DDR5 ECC RDIMM

Vendor เสนอ

DDR5 SO-DIMM

แม้เป็น DDR5 เหมือนกัน

ก็ไม่สามารถใช้แทนกันได้

036

ตัวอย่าง Software Compatibility

Application เก่า

รองรับ

Windows Server 2019

Vendor เสนอ Server ใหม่พร้อม

Windows Server Version ใหม่กว่า

Hardware ดีกว่า

แต่ Application อาจยังไม่ Certified

ต้องตรวจ Software Vendor

037

Version Compatibility

ตัวอย่าง

FortiGate ใช้ FortiOS Version หนึ่ง

ต้องการซื้อ

FortiAP รุ่นใหม่

ต้องตรวจว่า FortiOS ที่ใช้อยู่รองรับ FortiAP รุ่นนั้นหรือไม่

ถ้าไม่รองรับ

อาจต้อง Upgrade FortiOS

ซึ่งอาจกระทบระบบอื่น

038

Compatibility Matrix คืออะไร

Compatibility Matrix คือเอกสารที่บอกว่า

Product A

รองรับ

Product B / Version ไหน

ตัวอย่าง

  • Server + OS
  • Hypervisor + Hardware
  • Firewall + Access Point
  • Software + Database
  • OS + Application
039

EOL คืออะไร

EOL ย่อมาจาก

End of Life

หมายถึงสินค้าเข้าสู่ช่วงสิ้นสุดวงจรชีวิต

อาจหมายถึง

  • หยุดผลิต
  • หยุดจำหน่าย
  • มีรุ่นใหม่มาแทน

รายละเอียดขึ้นกับ Manufacturer

040

EOS คืออะไร

EOS มักใช้ในความหมายเกี่ยวกับ

End of Support

หรือชื่อ Lifecycle Stage ตามผู้ผลิต

หมายถึงช่วงที่ Support สิ้นสุด

ต้องตรวจคำจำกัดความของ Brand นั้นโดยตรง

041

ทำไม EOL / EOS สำคัญกับ Procurement

สมมติ Vendor เสนอ Firewall ราคาถูกมาก

แต่

EOL แล้ว

และเหลือ Support อีก 1 ปี

องค์กรต้องการใช้งาน 5 ปี

แม้ราคาถูก

ก็อาจสร้างปัญหาในอนาคต

MODULE 04 · TOPIC 046–054

Equivalent, Alternative, Comparison Table & Evidence

9 หัวข้อ
046

Equivalent Product

สินค้า Equivalent ควรมี

Function

ทำหน้าที่เดียวกัน

Specification

Requirement สำคัญครบ

Performance

เท่ากันหรือสูงกว่าในจุดที่จำเป็น

Compatibility

ใช้งานร่วมกับระบบได้

Support

Warranty / Lifecycle เหมาะสม

047

Alternative Product

Alternative คือสินค้าใกล้เคียงที่อาจใช้แทนได้

แต่มีบางจุดต่างจาก Requirement

ตัวอย่าง

Requirement

Notebook 14"

Alternative

Notebook 15.6"

Hardware อื่นทั้งหมดตรง

สามารถเสนอได้

แต่ต้องให้ IT/User ยืนยัน

048

Not Equivalent

สินค้าไม่ควรถูกเสนอว่า Equivalent หาก

  • Requirement สำคัญขาด
  • Performance ต่ำกว่าเกณฑ์
  • Interface ไม่ตรง
  • Software ไม่รองรับ
  • License ไม่ตรง
  • Warranty ต่ำกว่า
  • Product ใกล้หมด Support
049

ระดับผลการเปรียบเทียบ

ใช้ 3 ระดับ

✅ PASS / Equivalent

ตรง Requirement

⚠️ Conditional / Alternative

ต่างบางข้อ ต้องอนุมัติ

❌ FAIL / Not Equivalent

ไม่ผ่าน Requirement สำคัญ
