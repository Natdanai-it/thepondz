Promptข้อความที่เราพิมพ์สั่ง AI

02
พื้นฐาน Prompt

ทำไมพิมพ์แค่ “สร้างเว็บสวย ๆ” แล้วมักไม่ได้อย่างที่คิด

เพราะคำว่า “สวย” ของแต่ละคนไม่เหมือนกัน ถ้าเราไม่บอกกรอบ AI จะเลือกสี การจัดหน้า และลูกเล่นเอง

แบบที่กว้างเกินไป

“สร้างเว็บบริษัทสวย ๆ ทันสมัยให้หน่อย”

AI ต้องเดาแทบทุกอย่าง
แบบที่ชัดกว่า

“สร้างเว็บบริษัท IT โทนขาว-น้ำเงิน ดูมืออาชีพ หน้าแรกต้องเห็นบริการ ผลงาน และปุ่มติดต่อทันที รองรับมือถือ และไม่เอาแสง Glow”

AI รู้ทั้งเป้าหมาย หน้าตา และข้อห้าม
Prompt 01ให้ AI ถามเราก่อนเริ่มทำ
ฉันอยากสร้างเว็บไซต์ แต่รายละเอียดอาจยังไม่ครบ

ก่อนเขียนโค้ด ช่วยถามฉันทีละข้อเฉพาะเรื่องที่จำเป็น:
1. เว็บนี้ทำขึ้นเพื่ออะไร
2. ใครเป็นคนใช้
3. ต้องมีหน้าอะไรบ้าง
4. ต้องมีข้อมูลอะไร
5. อยากได้หน้าตาประมาณไหน
6. มีเว็บตัวอย่างที่ชอบไหม
7. ต้องรองรับมือถือหรือไม่
8. มีอะไรที่ไม่ต้องการให้ทำ

หลังจากฉันตอบครบแล้ว ให้สรุปสิ่งที่ฉันต้องการเป็นภาษาง่าย ๆ
ยังไม่ต้องเขียนโค้ด
เหมาะมากสำหรับคนที่ยังไม่รู้ว่าจะเริ่มอธิบายระบบจากตรงไหน
03
สูตรจำง่าย

Prompt ที่ดีควรบอก 8 เรื่องนี้

ไม่จำเป็นต้องใช้ศัพท์อังกฤษ แค่ตอบให้ครบว่า “ทำอะไร · ใครใช้ · มีอะไร · หน้าตาแบบไหน · ใช้งานยังไง”

Prompt 02ตัวอย่าง Prompt สำหรับเว็บ Portfolio
ช่วยสร้างเว็บไซต์ Portfolio สำหรับคนรับงาน IT

เป้าหมาย:
ให้คนที่เข้ามารู้ภายในไม่กี่วินาทีว่าฉันรับทำอะไร และสามารถดูผลงานหรือกดติดต่อได้ง่าย

คนที่เข้ามาดู:
- คนที่ต้องการ IT Support
- ธุรกิจที่ต้องการเว็บไซต์หรือระบบ
- คนที่สนใจเรียนคอมพิวเตอร์แบบตัวต่อตัว

ข้อมูลที่ต้องมี:
- แนะนำตัวสั้น ๆ
- บริการ
- คอร์ส
- โปรเจกต์ที่เคยทำ
- รีวิว
- ราคาเริ่มต้น
- ช่องทางติดต่อ

หน้าตา:
- ทันสมัย
- ดูเป็นมืออาชีพ
- พื้นหลังสว่าง
- ใช้รูปประกอบที่เกี่ยวข้องจริง
- ตัวหนังสืออ่านง่าย

การจัดหน้า:
หน้าแรก → บริการ → ผลงาน → คอร์ส → รีวิว → ราคา → ติดต่อ

การใช้งาน:
คนต้องกดไปดู “ผลงาน / คอร์ส / ติดต่อ” ได้ง่าย

มือถือ:
ต้องออกแบบใหม่ให้เหมาะกับมือถือ ไม่ใช่แค่ย่อหน้า Desktop

ไม่ต้องการ:
- แสง Glow
- Neon
- Gradient เยอะ
- การ์ดซ้ำ ๆ ทุก Section
- ช่องว่างยาวเกินไป
- Animation ที่รบกวนการอ่าน

ก่อนเขียนโค้ด ให้สรุปแผนหน้าเว็บก่อน
04
จากไอเดียสู่ระบบ

เปลี่ยนประโยคสั้น ๆ ให้ AI เข้าใจงานจริง

แทนที่จะบอกแค่ชื่อระบบ ให้ตอบ 4 คำถาม: “ใครใช้ / ทำอะไร / เก็บอะไร / เสร็จแล้วเห็นอะไร”

ไอเดียเดิม“อยากได้ระบบแจ้งซ่อม”
→
อธิบายให้ชัดขึ้นพนักงานแจ้งปัญหา → ช่างรับงาน → เปลี่ยนสถานะ → ผู้แจ้งกลับมาดูได้
Prompt 03แปลงไอเดียให้เป็นแผนระบบ
ฉันอยากทำ “ระบบแจ้งซ่อม”

คนที่ใช้:
- พนักงาน: แจ้งปัญหาและดูสถานะ
- ช่าง: ดูงานที่ได้รับและอัปเดตสถานะ
- Admin: ดูงานทั้งหมดและจัดการประเภทปัญหา

ข้อมูลที่ต้องเก็บ:
- หัวข้อ
- รายละเอียด
- รูปภาพ
- ผู้แจ้ง
- วันที่
- ผู้รับผิดชอบ
- สถานะ

ช่วยฉัน:
1. สรุปว่าระบบนี้ต้องมีอะไรบ้าง
2. แบ่งเป็น “จำเป็นตอนแรก” กับ “ทำเพิ่มทีหลัง”
3. เสนอหน้าที่ต้องมี
4. เสนอเส้นทางการใช้งานแบบง่าย
5. บอกข้อมูลที่ฉันยังไม่ได้ระบุ

ยังไม่ต้องเขียนโค้ด
05
วางหน้าเว็บ

ก่อนเลือกสี ต้องรู้ก่อนว่าคนจะเดินไปหน้าไหน

เว็บที่ใช้ง่ายไม่ได้เริ่มจากเอฟเฟกต์ แต่เริ่มจากการวางข้อมูลให้คนหาเจอเร็ว

Prompt 04ให้ AI วางหน้าและเส้นทางการใช้งาน
จากข้อมูลโปรเจกต์ที่สรุปไว้ ช่วยวางโครงหน้าเว็บก่อน

ขอผลลัพธ์เป็น:
1. ต้องมีหน้าอะไรบ้าง
2. แต่ละหน้ามีไว้ทำอะไร
3. หน้าแรกควรเรียง Section อะไรก่อน-หลัง
4. ปุ่มหลักของแต่ละหน้าควรเป็นอะไร
5. ถ้าเป็นมือถือ เมนูควรใช้อย่างไร
6. มีหน้าไหนที่ไม่จำเป็นหรือรวมกันได้บ้าง

อธิบายเป็นภาษาง่าย ๆ
ยังไม่ต้องเขียนโค้ด
06
กำหนดหน้าตา

อย่าบอกแค่ “สวย” ให้บอกว่าอยากให้เว็บรู้สึกแบบไหน

เลือก 3–5 คำที่บอกอารมณ์ของงาน เช่น เรียบ, มืออาชีพ, เป็นมิตร, ทันสมัย, Premium แล้วบอกสิ่งที่ “ไม่เอา” ด้วย

เรียบและมืออาชีพสีไม่เยอะ · ฟอนต์ชัด · ช่องว่างพอดี
ทันสมัยแบบ SoftwareCard ใช้เท่าที่จำเป็น · มีภาพหน้าจอ · ปุ่มชัด
เป็นมิตรภาษาอ่านง่าย · รูปภาพจริง · ไม่แข็งเกินไป
สิ่งที่ไม่เอาGlow · Neon · ของลอยเยอะ · Animation เกินจำเป็น
Prompt 05กำหนดแนวหน้าตาแบบเข้าใจง่าย
ช่วยกำหนดแนวหน้าตาของเว็บนี้ก่อนสร้างจริง

ฉันต้องการ:
- ทันสมัย
- ดูเป็นมืออาชีพ
- อ่านง่าย
- ไม่แน่นเกินไป
- ใช้รูปหรือภาพประกอบที่มีความหมาย
- สีหลักไม่เกิน 2–3 สี
- ปุ่มหลักต้องเด่นกว่าปุ่มรอง

ช่วยกำหนด:
- สีหลัก / สีพื้น / สีข้อความ
- ฟอนต์และขนาดหัวข้อ
- ระยะห่าง
- รูปแบบปุ่ม
- รูปแบบ Card
- รูปแบบภาพประกอบ
- วิธีจัดหน้าในมือถือ

สิ่งที่ไม่ต้องการ:
- Glow
- Neon
- Gradient เยอะ
- เงาหนัก
- Card ทุกอย่าง
- Animation ที่ทำให้เวียนหัว

ยังไม่ต้องเขียนโค้ด
07
รูปประกอบ

เว็บดูดีขึ้นเมื่อใช้ “รูปที่ช่วยเล่าเรื่อง” ไม่ใช่ใส่รูปเพราะมีที่ว่าง

ให้ AI บอกก่อนว่า Section ไหนควรใช้ภาพจริง ภาพหน้าจอ หรือภาพประกอบ แล้วค่อยใส่ลงเว็บ

ภาพจริงเหมาะกับบริการ / คน / ผลงานจริง
ภาพหน้าจอเหมาะกับเว็บ / Dashboard / ระบบ
ภาพประกอบเหมาะกับเรื่องที่อธิบายด้วยภาพง่ายกว่า
Prompt 06ให้ AI วางแผนว่าจะใช้รูปตรงไหน
ตรวจโครงหน้าเว็บนี้ แล้วช่วยบอกว่า Section ไหน “ควรมีรูป” และควรเป็นรูปแบบไหน

เลือกได้จาก:
- ภาพถ่ายจริง
- Screenshot ผลงาน
- ภาพประกอบแบบเรียบ
- Icon
- ไม่ต้องใช้รูป

สำหรับแต่ละ Section ขอ:
1. ควรใช้รูปหรือไม่
2. ใช้รูปประเภทไหน
3. รูปควรสื่ออะไร
4. ควรวางซ้าย/ขวา/เต็มความกว้าง
5. มือถือควรแสดงรูปอย่างไร

หลีกเลี่ยงรูป Stock ที่ไม่เกี่ยวข้องกับเนื้อหา
08
ใช้เว็บตัวอย่าง

ถ้าชอบเว็บใคร ให้ AI วิเคราะห์ “สิ่งที่ชอบ” แทนการสั่งว่าลอกให้เหมือน

ตัวอย่างเช่น ชอบการเรียง Section, ขนาดตัวหนังสือ, การแสดงผลงาน หรือความโล่งของหน้า ไม่จำเป็นต้องลอกสีและข้อความทั้งหมด

Prompt 07วิเคราะห์เว็บตัวอย่าง
นี่คือเว็บตัวอย่างที่ฉันชอบ:
[ใส่ลิงก์เว็บ]

ช่วยวิเคราะห์ให้หน่อยว่าเว็บนี้ดูดีเพราะอะไร โดยดูเฉพาะ:
- การเรียงข้อมูล
- การใช้พื้นที่
- ขนาดหัวข้อ
- ตำแหน่งปุ่ม
- วิธีแสดงผลงาน
- วิธีใช้รูป
- การจัดหน้าในมือถือ

จากนั้นช่วยเสนอแนวทาง “ใหม่” สำหรับเว็บของฉัน
ห้ามลอกชื่อ ข้อความ โลโก้ สี หรือรูปเฉพาะของเว็บต้นฉบับ
ประโยคที่ดี: “ชอบวิธีจัดผลงานเป็นการ์ดแนวนอนและมีภาพใหญ่” ดีกว่า “ทำเหมือนเว็บนี้เลย”
09
เริ่มสร้างจริง

เมื่อแผนชัดแล้ว ค่อยให้ AI เขียนเว็บ

สั่งให้ทำทีละส่วนจะตรวจง่ายกว่า และถ้าพังก็รู้ว่าพังจากตรงไหน

Prompt 08Master Prompt สำหรับเริ่มสร้างเว็บ
ตอนนี้เราได้ข้อสรุปเรื่องโครงหน้าและหน้าตาแล้ว
เริ่มสร้างเว็บไซต์ตามแผนที่ตกลงกัน

กติกา:
- ทำทีละ Section
- เริ่มจาก Header + Hero ก่อน
- เมื่อทำเสร็จให้หยุดและสรุปว่าทำอะไรไป
- อย่าเพิ่ม Section ที่ฉันไม่ได้ขอ
- ใช้รูปประกอบหรือ Placeholder เฉพาะตำแหน่งที่จำเป็น
- รองรับมือถือ แท็บเล็ต และคอม
- ห้ามมี Horizontal Scroll
- ปุ่มต้องกดง่ายบนมือถือ
- ตัวหนังสือต้องไม่เล็กเกินไป
- ไม่ใช้ Glow / Neon / Animation เยอะ

ก่อนแก้ไฟล์ ให้ดูไฟล์เดิมก่อน
ถ้ามีของเดิมที่ใช้งานได้ ให้เก็บไว้
Prompt นี้เหมาะสำหรับใช้กับ Claude Code หรือ AI Coding Tool ที่เปิดอยู่ในโฟลเดอร์โปรเจกต์

สั่งแก้ให้สวยขึ้น

จุดสำคัญที่สุด: อย่าพิมพ์ว่า “ไม่สวย ทำใหม่”

บอกให้ชัดว่าตรงไหนมีปัญหา เช่น หัวข้อไม่เด่น ช่องว่างเยอะ ปุ่มดูเหมือนกัน หรือรูปไม่ช่วยเล่าเรื่อง

“มันโล่งไป”→ ลดช่องว่างแนวตั้ง และดึงข้อมูลสำคัญขึ้นมาใกล้กันมากขึ้น
“หัวข้อไม่เด่น”→ ทำให้หัวข้อหลักเด่นที่สุด และลดน้ำหนักข้อความรอง
“ปุ่มแปลก”→ ทำให้ปุ่มหลักเด่นกว่าปุ่มรองอย่างชัดเจน
“มือถือดูยัด”→ จัดองค์ประกอบมือถือใหม่ ไม่ใช่ย่อจาก Desktop อย่างเดียว
Prompt 09แก้เฉพาะ Hero ไม่ให้ AI รื้อทั้งเว็บ
อย่าออกแบบใหม่ทั้งเว็บไซต์
แก้เฉพาะ Hero Section เท่านั้น

ปัญหาที่เห็น:
- หัวข้อยังไม่เด่น
- ช่องว่างเยอะเกินไป
- รูปด้านขวายังไม่ช่วยอธิบายบริการ
- ปุ่มหลักกับปุ่มรองดูเด่นเท่ากัน

ขอให้:
1. ปรับลำดับความเด่นของข้อความ
2. ลดพื้นที่ว่างที่ไม่จำเป็น
3. ทำปุ่มหลักให้เด่นขึ้น
4. ใช้ภาพประกอบที่สื่อถึงบริการจริง
5. ตรวจมือถือด้วย

ห้ามแก้ Navigation และ Section อื่น
หลังแก้ให้สรุปว่าปรับตรงไหนบ้าง
11
Website vs Web App

เว็บแนะนำบริการกับระบบใช้งานจริง สั่ง AI ไม่เหมือนกัน

Website เน้นให้คนอ่านและตัดสินใจ ส่วน Web App เน้นให้คนทำงาน เช่น กรอกฟอร์ม อนุมัติ ค้นหา และดูสถานะ

Prompt 10Prompt สำหรับ Web App
ช่วยออกแบบ Web App สำหรับระบบคำขอภายในบริษัท

ผู้ใช้:
- พนักงาน: สร้างคำขอและดูสถานะ
- หัวหน้า: อนุมัติหรือปฏิเสธ
- Admin: ดูทั้งหมดและตั้งค่าระบบ

งานหลัก:
- กรอกคำขอ
- แนบไฟล์
- ดูสถานะ
- อนุมัติ / ปฏิเสธ
- ค้นหาและกรองรายการ

ขอให้เน้น “ใช้งานง่าย” มากกว่าตกแต่ง
ทุกหน้าต้องบอกให้ผู้ใช้รู้ว่าต้องทำอะไรต่อ

ช่วยออกแบบ:
- หน้า Dashboard
- ฟอร์มสร้างคำขอ
- หน้ารายละเอียด
- หน้ารออนุมัติ
- หน้าจัดการของ Admin

และต้องมีสถานะ:
กำลังโหลด / ไม่มีข้อมูล / สำเร็จ / ผิดพลาด / ปุ่มกดไม่ได้ / ยืนยันก่อนลบ
12
หน้าจอต้องบอกสถานะ

ระบบที่ดู “ครบ” ต้องคิดตอนที่ยังไม่มีข้อมูลและตอนที่เกิดปัญหาด้วย

มือใหม่มักออกแบบเฉพาะตอนทุกอย่างทำงานปกติ แต่ผู้ใช้จริงจะเจอ Loading, Error และข้อมูลว่างแน่นอน

กำลังโหลดบอกว่าระบบกำลังทำงาน
ยังไม่มีข้อมูลบอกว่าต้องเริ่มจากอะไร
สำเร็จยืนยันว่าบันทึกแล้ว
ผิดพลาดบอกสาเหตุและวิธีลองใหม่
กดไม่ได้ปิดปุ่มเมื่อข้อมูลยังไม่ครบ
ยืนยันก่อนทำเช่น ลบข้อมูลหรืออนุมัติรายการ
Prompt 11ให้ AI เติมสถานะที่ขาด
ตรวจ Web App นี้ว่ามีหน้าจอรองรับสถานการณ์เหล่านี้ครบหรือยัง:
- กำลังโหลด
- ไม่มีข้อมูล
- บันทึกสำเร็จ
- เกิดข้อผิดพลาด
- ไม่มีสิทธิ์
- ปุ่มยังไม่สามารถกดได้
- ยืนยันก่อนลบหรือทำรายการสำคัญ

ถ้ายังขาด ให้เพิ่มข้อความและหน้าตาที่เข้าใจง่าย
อย่าเพิ่ม Animation ที่ไม่จำเป็น
13
มือถือ / แท็บเล็ต / คอม

รองรับมือถือ ไม่ใช่แค่ย่อทุกอย่างให้เล็ก

บางอย่างต้อง “เปลี่ยนวิธีแสดง” เช่น ตารางใหญ่ในคอม อาจกลายเป็น Card ในมือถือ

Prompt 12ตรวจ Responsive แบบภาษาง่าย
ช่วยตรวจเว็บนี้ในขนาดหน้าจอ:
320, 375, 430, 768, 1024 และ 1440px

เช็กเรื่อง:
- มีอะไรล้นออกนอกจอไหม
- ตัวหนังสือถูกตัดไหม
- หัวข้อใหญ่เกินไปไหม
- ปุ่มเล็กเกินไปไหม
- Card แคบจนอ่านยากไหม
- ตารางใช้บนมือถือได้ไหม
- เมนูเปิด/ปิดได้ไหม
- Modal ปิดได้ไหม
- รูปถูกตัดแปลกไหม
- มีช่องว่างยาวเกินไปไหม

ถ้าส่วนไหนไม่เหมาะกับมือถือ ให้ “จัดใหม่สำหรับมือถือ”
ไม่ต้องพยายามให้เหมือน Desktop ทุกอย่าง
Prompt 13เปลี่ยนตารางเป็น Card ในมือถือ
ตารางนี้อ่านยากบนมือถือ

ขอให้:
- Desktop ยังใช้ตารางเหมือนเดิม
- หน้าจอต่ำกว่า 640px ให้เปลี่ยนเป็น Card
- ใน Card ให้แสดงข้อมูลสำคัญก่อน
- สถานะต้องเห็นชัด
- ปุ่มต้องกดง่ายด้วยนิ้ว
- ห้ามทำให้ข้อมูลหาย

แก้เฉพาะส่วนแสดงผล ไม่ต้องเปลี่ยนข้อมูลหรือระบบหลังบ้าน
