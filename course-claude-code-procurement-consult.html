เริ่มจากระบบจริง

ระบบนี้ “ไม่ใช่แค่เว็บ” แล้ว แต่เป็นระบบงานพัสดุค่อนข้างครบ

จากตัวอย่างหน้าจอของระบบ เห็นทั้ง Dashboard งบประมาณ, แผนจัดซื้อ, TOR/คุณลักษณะ, สัญญา, หลักประกัน, ตรวจรับ, ทะเบียนคุมเลข, ทะเบียนตรวจเอกสาร, ครุภัณฑ์, หนังสือ/อุปกรณ์การเรียน และรายงาน/Audit Trail

ภาพรวมสิ่งที่ระบบนี้กำลังเชื่อมกัน
จุดแข็งที่เห็นเมนูเป็นระบบ, Dashboard เห็นเงินและสถานะ, มี Dark Mode, มีค้นหา/กรอง, มีสถานะความคืบหน้า, มี Audit/Readiness Report
คำถามสำคัญต่อไปข้อมูลจริงเก็บที่ไหน? Login จริงหรือยัง? หลายคนใช้พร้อมกันได้ไหม? มี Backup ไหม? ใครมีสิทธิ์แก้อะไร?
01
เรื่องที่ต้องรู้ก่อน Deploy

ข้อแรกที่ต้องเช็ก: “ข้อมูลเก็บอยู่ที่ไหน?”

หน้าจอสวยอย่างเดียวไม่ได้แปลว่าระบบพร้อมใช้หลายคน ถ้าข้อมูลเก็บแค่ใน Browser หรือไฟล์ JSON พอเปลี่ยนเครื่อง ข้อมูลอาจไม่ตามไปด้วย

จำแค่นี้หน้าจอ กับ ที่เก็บข้อมูล เป็นคนละเรื่อง
ถ้าเป็น localStorage / JSON

เหมาะสำหรับทำต้นแบบหรือใช้เครื่องเดียว แต่ไม่เหมาะเป็นฐานข้อมูลกลางของงานจัดซื้อจริง

ถ้าเป็น Database เช่น Google Sheets + Apps Script/Firebase

หลายเครื่องเห็นข้อมูลชุดเดียวกัน ทำ Login, Role, Backup และประวัติการแก้ไขได้ง่ายกว่า

PROMPT 01ให้ Claude หาให้ว่า “ข้อมูลเก็บที่ไหน”
ช่วยตรวจ Project นี้ก่อน โดยยังไม่แก้ Code

ฉันอยากรู้เรื่อง “การเก็บข้อมูล” ของระบบนี้

ช่วยหาและอธิบายแบบง่าย ๆ ว่า:

ถ้าจะพัฒนาต่อ ผมให้ความสำคัญ 5 อย่างนี้ก่อนลูกเล่นใหม่

ระบบนี้มี Feature เยอะแล้ว สิ่งที่ควรเพิ่มไม่ใช่ “เมนูเพิ่ม” แต่คือทำให้ข้อมูลน่าเชื่อถือ ปลอดภัย และย้อนดูได้

1Login + Role

Admin, เจ้าหน้าที่พัสดุ, ผู้ดูอย่างเดียว ควรทำได้ไม่เท่ากัน

2Audit Trail

3Backup / Restore

เผลอลบหรือข้อมูลเสีย ต้องกู้กลับได้

4Validation

กันวันที่ผิด, เงินติดลบ, งบเกิน, เลขเอกสารซ้ำ

ยอดใน Dashboard, สัญญา และรายงานควรดึงจากข้อมูลต้นทางเดียวกัน

05
Deploy ฟรีและง่าย

สำหรับใช้คนเดียว: Apps Script Web App ง่ายที่สุด

ถ้าต้องการฟรี ใช้คนเดียว และข้อมูลอยู่ใน Google Sheets วิธีที่ง่ายที่สุดคือ Deploy หน้าเว็บผ่าน Google Apps Script โดยตรง ไม่จำเป็นต้องแยก GitHub Pages หรือ Cloudflare Pages

ตัดสินใจเริ่มจาก Demo หรือระบบใช้จริง?
Apps Script Web Appแนะนำที่สุด

หน้าเว็บ + Backend + Google Sheet อยู่ในระบบ Google ชุดเดียว Deploy ได้จากเมนู Apps Script

เหมาะกับระบบใช้คนเดียว
GitHub Pagesใช้ได้ แต่ไม่จำเป็น

เหมาะถ้าต้องการแยก Frontend ออกจาก Apps Script แต่จะซับซ้อนขึ้นเรื่องการเชื่อม API

คอร์สนี้ไม่เลือกทางนี้เพื่อให้ง่ายที่สุด
สำหรับระบบโรงเรียนจริง: ถ้ามีข้อมูลจัดซื้อจริง ผู้ขาย เอกสาร หรือข้อมูลผู้ใช้ อย่าเอาข้อมูลจริง/รหัสลับไว้ใน Public GitHub Repo และอย่าใช้ localStorage เป็นฐานข้อมูลหลัก

06
ทำตามได้ในคลาส

Deploy แบบที่ควรสอนจริง: 2 วิธีพอ

ไม่ต้องสอน AWS ในคลาสนี้ก่อน เพราะเป้าหมายของผู้เรียนคือ “ฟรี ง่าย และทำต่อเองได้”

A. GitHub Pagesเหมาะเมื่อเป็น Static
  1. สร้าง Repository ใน GitHub
  2. Push/Upload Code ขึ้น Repo
  3. เข้า Settings → Pages
  4. เลือก Deploy จาก Branch ที่ใช้ เช่น main
  5. รอ GitHub สร้าง URL username.github.io/repository
ถ้า Project ใช้ Vite/React อาจต้อง Build ก่อนหรือใช้ GitHub Actions — ให้ Claude อ่าน Project แล้วบอกวิธีที่ถูกต้อง
B. Cloudflare Pagesเหมาะ Frontend และต่อ Git ง่าย
  1. Push Code ขึ้น GitHub
  2. เข้า Cloudflare → Workers & Pages
  3. สร้าง Pages Project และ Connect Git Repository
  4. ใส่ Build command / Output directory ตาม Project
  5. กด Deploy — หลังจากนั้น Push Git ครั้งใหม่ ระบบ Build ให้ใหม่อัตโนมัติ
PROMPT 09ให้ Claude เตรียม Project ก่อน Deploy
ฉันจะ Deploy Project นี้

ก่อนทำจริง ช่วยตรวจ:
- มีไฟล์หรือ Path ที่ใช้ localhost อยู่หรือไม่
- มี Secret/API Key อยู่ใน Code หรือไม่
- มี .env หรือไม่
- Build command คืออะไร
- Output folder คืออะไร
- ถ้าเปิด URL ย่อย Routing จะพังหรือไม่
- มีไฟล์ที่ไม่ควร Push ขึ้น GitHub หรือไม่

จากนั้นสร้าง Checklist ให้ฉันทีละขั้น

07
GOOGLE SHEETS + APPS SCRIPT

ทางที่ง่ายที่สุดสำหรับใช้คนเดียว: Google Sheets เป็นฐานข้อมูล + Apps Script เป็น Web App

สำหรับระบบนี้ ถ้าเป้าหมายคือ “ใช้ฟรี ใช้คนเดียว เปิดจากคอมเครื่องไหนก็ได้ และไม่อยากดูแล Server” วิธีที่ง่ายกว่าการต่อ Google Sheets + Apps Script คือใช้ Google Sheets เก็บข้อมูล และใช้ Google Apps Script เป็นหลังบ้านและหน้า Web App

โครงสร้างที่แนะนำ:
หน้าเว็บ: Apps Script HTML Service
เก็บข้อมูล: Google Sheets
เก็บไฟล์: Google Drive
Deploy: Apps Script Web App
ผู้ใช้: เจ้าของระบบ 1 คน
เหมาะกับระบบนี้ตอนนี้

ถ้าใช้คนเดียว เป็นระบบช่วยงานส่วนตัว และข้อมูลยังไม่ใหญ่มาก วิธีนี้ง่ายและดูแลง่ายที่สุด

F. อ่านข้อมูลจาก Google Sheet

Code.gs — อ่าน Sheet Procurement 
function getProcurement() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const sheet = ss.getSheetByName('Procurement');

  const values = sheet.getDataRange().getValues();
  const headers = values.shift();

  return values.map(row => {
    const item = {};
    headers.forEach((key, i) => item[key] = row[i]);
    return item;
  });
}
Index.html — เรียกข้อมูลจาก Apps Script

G. บันทึกข้อมูลลง Google Sheet

Code.gs — เพิ่มรายการใหม่ 
function addProcurement(form) {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const sheet = ss.getSheetByName('Procurement');

  const id = Utilities.getUuid();
  const now = new Date();

  sheet.appendRow([
    id,
    form.doc_no,
    form.title,
    form.department,
    Number(form.budget || 0),
    'draft',
    0,
    now,
    now
  ]);

  return { success: true, id };
}
