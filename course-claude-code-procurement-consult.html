02
BUSINESS FLOW

วาง Flow งานจัดซื้อก่อนเพิ่ม Feature

ระบบจัดซื้อไม่ได้มีแค่ “ฟอร์มขอซื้อ” แต่มีคนหลายบทบาท สถานะหลายขั้น และประวัติที่ต้องย้อนดูได้

PROMPT 02ให้ Claude ช่วยตรวจ Flow งานจัดซื้อ
This project is a procurement management system.

Current workflow:
1. User creates Purchase Request
2. Manager reviews the request
3. Procurement receives approved request
4. Procurement requests quotations from vendors
5. Quotations are compared
6. Selected quotation is approved
7. Purchase Order is created
8. Delivery is tracked
9. Purchase is completed

For each step, explain:
- Who uses it
- What data is required
- What status should exist
- What actions are allowed
- What happens next

Also identify missing steps.

Use simple language.
Do not write code yet.
03
USER ROLE

Login ได้ ไม่ได้แปลว่าทำได้ทุกอย่าง

อธิบายง่าย ๆ: Login = “คุณคือใคร” ส่วน Permission = “คุณมีสิทธิ์ทำอะไร”

Roleงานหลักตัวอย่างสิทธิ์
Requesterสร้างคำขอซื้อดู/แก้ของตัวเองก่อนส่ง
Managerตรวจและอนุมัติดูงานของทีม
ProcurementVendor / RFQ / Quote / POจัดการงานหลังอนุมัติ PR
Financeตรวจงบ/เงื่อนไขเห็นข้อมูลด้านงบที่เกี่ยวข้อง
Adminตั้งค่าระบบUser / Master Data / Permission
PROMPT 03ออกแบบสิทธิ์แต่ละ Role
Help me design user roles for this procurement system.

Roles:
- Requester
- Manager
- Procurement
- Finance
- Admin

Create a simple permission table showing:
- What each role can view
- What each role can create
- What each role can edit
- What each role can approve
- What each role must not access

Keep permissions simple and secure.
Do not implement them yet.

07
DEPLOY

GitHub Pages หรือ AWS? ต้องดูชนิดของ Project ก่อน

อย่าเลือก Hosting จากชื่อที่คุ้น ให้ดูว่าระบบมี Backend, Database, Server-side Code และ Environment Variables หรือไม่

ตัวเลือกเหมาะกับจำง่าย
GitHub Pagesเว็บ Static / HTML CSS JSง่ายและฟรี แต่ไม่มี Backend Server ของตัวเอง
AWS AmplifyFrontend / SPA / Framework ที่เชื่อม GitPush GitHub แล้ว Build/Deploy ต่อได้
AWS App Runner / ServerApp ที่ต้องรัน Backendใช้เมื่อมี Server-side/API ที่ต้องทำงานตลอด
S3 + CloudFrontStatic Site ที่ต้องการ CDN/การควบคุมมากขึ้นเร็วและยืดหยุ่น แต่ตั้งค่ามากกว่า
PROMPT 09ให้ Claude วิเคราะห์ว่า Project ควร Deploy ที่ไหน
Please analyze this actual project and recommend the simplest deployment option.

Consider:
- GitHub Pages

- AWS App Runner
- VPS / traditional server

Explain:
1. Is this a static website or a web application?
2. Does it need a backend?
3. Does it need a database?
4. Does it use server-side code?
5. Does it need environment variables?
6. Which option is simplest?
7. Which option is suitable for production?
8. What would the basic architecture look like?

Do not deploy anything yet.
08
BEFORE DEPLOY

ก่อนขึ้นระบบจริง ให้ตรวจ 7 จุดนี้

หลายระบบทำงานในเครื่อง แต่พอขึ้น Hosting แล้วพังเพราะ URL, Environment Variables, CORS หรือ Build Command

✓ Build command
✓ Output folder
✓ Environment Variables
✓ API URL
✓ Database config
✓ CORS / Domain
✓ Secret ไม่อยู่ใน Source
✓ Production test

09
SECURITY

.env คือที่เก็บค่าลับ ไม่ใช่ของที่ควรเอาขึ้น GitHub

ตัวอย่างค่าที่ควรระวัง: API Key, Database Password, Secret Token, Private Key

ไม่ควรทำ
const API_KEY = "my-real-secret-key";
Secret ฝังอยู่ใน Source Code
แนวคิดที่ควรใช้
API_KEY=...
DATABASE_URL=...
เก็บใน Environment Variables / .env และไม่ Commit ค่า Secret
