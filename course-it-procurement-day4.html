02

5 คำถามที่ใช้ได้กับแทบทุก Product

  1. What? สินค้าหรือบริการคืออะไร
  2. Purpose? ใช้แก้ปัญหาหรือทำงานอะไร
  3. License? คิดสิทธิ์ใช้งานอย่างไร
  4. Dependency? ต้องทำงานร่วมกับอะไร
  5. Renewal? มีค่าใช้จ่ายต่อเนื่องหรือไม่

ถ้าตอบ 5 ข้อนี้ได้ จะเริ่มอ่าน Requirement และ Quotation ได้ถูกทาง แม้ยังไม่รู้รายละเอียดเชิงเทคนิคทุกตัว

03

คำว่า Brand อย่างเดียวไม่พอ

ชื่อ Brand มักยังไม่เพียงพอต่อการขอราคา เช่น Microsoft อาจหมายถึง Microsoft 365, Azure, Dynamics, Power BI, Windows หรือ SQL Server

เช่นเดียวกับ Dell อาจเป็น Notebook, Server, Storage หรือ Monitor และ Fortinet อาจเป็น FortiGate, FortiSwitch, FortiAP หรือ Security Subscription

ก่อนขอราคา ควรระบุ Product Family, Module/Edition, Quantity, License Term และ Scope ให้ชัดที่สุด

04

ERP คืออะไร

ERP — Enterprise Resource Planning คือระบบกลางที่เชื่อมกระบวนการธุรกิจหลายฝ่าย เช่น Sales, Purchasing, Inventory, Finance และ Operation ให้ใช้ข้อมูลร่วมกัน

ตัวอย่าง Flow: Sales Order → ตรวจ Stock → จัดส่ง → Invoice → Accounts Receivable

หากไม่มี ERP แต่ละฝ่ายอาจใช้ Excel หรือระบบแยกกัน ทำให้ข้อมูลซ้ำและตรวจสอบยาก

05

Microsoft Dynamics 365 คืออะไร

Dynamics 365 เป็นกลุ่ม Business Applications ของ Microsoft ไม่ใช่โปรแกรมตัวเดียว ภายในมีหลาย Module สำหรับงานคนละประเภท เช่น Finance, Supply Chain Management, Sales, Field Service และอื่น ๆ

06

Dynamics 365 Supply Chain Management

เน้นบริหาร Supply Chain และ Operations เช่น Procurement, Inventory, Warehouse, Manufacturing, Planning และ Logistics

ตัวอย่าง Procurement: Purchase Requisition → Purchase Order → Receiving → Inventory → Invoice

เหมาะกับองค์กรที่ต้องการควบคุมวัตถุดิบ สินค้า คลัง และกระบวนการผลิต/กระจายสินค้าเป็นระบบ

07

Dynamics 365 Finance

เน้นด้านการเงินและบัญชี เช่น General Ledger, Accounts Payable, Accounts Receivable, Cash, Budget, Fixed Asset และ Financial Reporting

ตัวอย่าง: บริษัทซื้อ Server → รับ Invoice → Accounts Payable → Payment → ลงทะเบียน Asset → คำนวณค่าเสื่อมราคา

08

Finance กับ Supply Chain ต่างกันอย่างไร

Dynamics 365 Finance

เงิน บัญชี งบประมาณ ภาษี เจ้าหนี้ ลูกหนี้ และ Financial Reporting

Dynamics 365 SCM

สินค้า การจัดซื้อ คลัง การผลิต การวางแผน และ Logistics

สองระบบมักเชื่อมกัน เช่น SCM รับสินค้าเข้า Warehouse แล้วส่งข้อมูล Invoice/Cost ไปยัง Finance

09

Dynamics 365 Business Central

Business Central เป็น ERP ของ Microsoft ที่ครอบคลุม Finance, Sales, Purchasing, Inventory, Project และ Operations ในแพลตฟอร์มเดียว

โดยทั่วไปเหมาะกับองค์กรขนาดเล็กถึงกลางหรือ Process ที่ไม่ซับซ้อนเท่าการใช้งาน Dynamics 365 Finance + Supply Chain Management แยกเป็น Enterprise Module

อย่าเปรียบราคา Business Central กับ Finance/SCM โดยไม่เทียบ Scope เพราะ Scale และ Capability แตกต่างกัน

ตัวอย่าง Plan จริง — Business Central

Essentials

Finance, Sales, Purchasing, Inventory และงานหลักของ ERP

Premium

เพิ่มความสามารถกลุ่ม Manufacturing / Service Management ในบริบทที่เกี่ยวข้อง

Team Members

สิทธิ์ใช้งานแบบจำกัดสำหรับผู้ใช้ที่ไม่ได้ต้องใช้ Full ERP Function

Procurement Example: เวลาขอราคาอย่าเขียนแค่ “Business Central 50 Users” — ต้องระบุ User Type / Plan ให้ชัด

10

Dynamics 365 Sales

Dynamics 365 Sales เป็นระบบ CRM สำหรับบริหาร Lead, Opportunity, Customer, Sales Pipeline, Quote และ Activity ของทีมขาย

Flow ตัวอย่าง: Lead → ติดต่อ → Opportunity → Quotation → Order → Customer

11

Dynamics 365 Field Service

ใช้บริหารงานบริการภาคสนาม เช่น Technician, Work Order, Schedule, Spare Parts, Customer Site และ Service History

ตัวอย่าง: ลูกค้าแจ้งเครื่องเสีย → เปิด Work Order → จัด Technician → ไปหน้างาน → ใช้อะไหล่ → ปิดงาน → บันทึกประวัติ

12

Dynamics 365 with Copilot

Copilot เป็น AI Assistant ที่ถูกนำไปใช้ในหลายผลิตภัณฑ์ของ Microsoft เพื่อช่วยสรุปข้อมูล ร่างข้อความ ค้นข้อมูล หรือช่วยวิเคราะห์ข้อมูลธุรกิจ

สำหรับ Procurement ควรตรวจให้ชัดว่า Copilot Feature ที่ Vendor เสนออยู่ใน Product/Module/License ใด เพราะคำว่า “with Copilot” ไม่ได้เป็น SKU เดียวตายตัวทุกกรณี

13

LS Retail / LS Central

LS Retail เป็น Solution ด้าน Retail โดยมี Product ที่พบเช่น LS Central สำหรับบริหาร POS, Store, Inventory, Promotion, Loyalty และ Retail Operations

ตัวอย่าง: Scan Barcode ที่ POS → รับ Payment → ตัด Stock → ส่งข้อมูลเข้าระบบหลังบ้าน

LS Retail สามารถทำงานร่วมกับ ERP ในบาง Architecture จึงไม่จำเป็นต้องมองว่าเป็นคู่แข่งตรงกับ ERP ทุกกรณี

Copilot Studio

ตัวอย่าง: Procurement Assistant ตอบ Policy การขอซื้อ หรือรับคำถาม “PO 1234 อยู่สถานะไหน?” แล้วไปดึงข้อมูลจากระบบที่เชื่อมไว้

AI Agent คืออะไร

AI Agent ถูกออกแบบให้ทำมากกว่าการตอบข้อความ โดยสามารถรับเป้าหมาย เรียกข้อมูล/Tool ดำเนิน Workflow และส่งผลกลับตามสิทธิ์ที่กำหนด

ตัวอย่าง: “หารายการ License ที่หมดอายุภายใน 60 วัน” → อ่านรายการ → Filter → สร้าง Report → ส่งแจ้งเตือน

Copilot vs Agent

Copilot

เน้นช่วยผู้ใช้ทำงาน โดยผู้ใช้ยังเป็นคนสั่งและตัดสินใจหลัก

Agent

สามารถออกแบบให้ดำเนินงานหลายขั้นตอนและใช้ Tool/Workflow ได้มากขึ้น

สำหรับ Procurement ให้ดู License, Connector, Capacity, Data Access และ Security มากกว่าคำว่า “AI” อย่างเดียว

Dell Server — PowerEdge
